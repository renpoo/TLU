# Sample 7: 現金決済流体システム (Cash Flow Mode) README

本サンプルは、株式市場の取引ネットワークから**「現金の決済移動と滞留」**のみを抽出し、貸借（B/S）が完璧に一致した閉じた物理・数理システムとしてモデル化したものです。

---

## 1. エグゼクティブ・サマリー（結論）

* **物理的・会計的結論**:
  本システムは、取引の決済手段である「現金（CASH）」の保存則を厳密に成立させています。初期状態の全プレイヤーの現金総額を `ACC_Input_From_Outside` （純資産 / Equity）として貸方に計上することで、貸借一致をスタート時点から保証し、全期間を通じて財務諸表の不一致が $0.00$（**`✅ BALANCED`**）となる完全な数理的整合性を達成しました。
* **ビジネス上の意義**:
  取引に伴う実際のキャッシュの動きを追跡し、**「資金がどこに滞留しているか（デッドロック）」「決済摩擦（手数料や流出）がどこで発生しているか」**という実体的な支払流動性を可視化・監査します。

---

## 2. モデル構築 of Duality & Pruning

原本となる取引仕訳（`Dummy_Market_Stream_Raw.csv`）から、以下のルールに基づいて「現金（CASH）の動き」だけを剪定・再構成しています。

1. **取引データの抽出**:
   * アセットタイプが「CASH」の取引のみを抽出。
   * 取引金額（`Transaction_Amount`）は、決済された現金の額面通り（`Amount`）として記録します。
   * ノードのサフィックス（`_Cash`）を除去し、`USR_001` や `USR_002` に表記を統一。
2. **初期状態（Day 0）の貸借一致**:
   * 資産側：各ユーザーの初期現金残高の合計（`USR_001`〜`USR_010`）
   * 負債・純資産側：システム外からの初期投入資金の総額（`ACC_Input_From_Outside` / 純資産として計上）
   * これにより、開始時点で資産の部（現金）と純資産の部（外部投入資本）が 1 円単位で完全に一致し、完璧にバランスしたクローズド・システムが形成されます。

---

## 3. TLU数理指標の会計ドメイン翻訳 (Rosetta Stone)

TLUの物理・数理フィルターが検出する各指標は、現金システムにおいて以下のような実務的な意味に翻訳されます。

| TLU物理指標 | 会計・ビジネスドメインでの実務的意味 |
| :--- | :--- |
| **Viscosity（粘性）** | **現金の決済流動性の重さ（資金の目詰まり・支払遅延）**<br>粘性が高い状態は、プレイヤー間で現金の移動が鈍くなり、決済流動性が低下している（資金ショートのリスクが高まっている）ことを示します。 |
| **Structural Stiffness（構造剛性）** | **資金循環の硬直度**<br>剛性が高い（Stiff）と、特定の取引ルートや預金口座に現金が固定化され、環境の変化に対して資金を機動的に再配分しにくくなっている状態を指します。 |
| **Entropy（エントロピー）** | **現金の偏在度**<br>エントロピーの急激な低下は、特定の口座への現金の不自然な集中（資金移動の偏り、マネーロンダリング、あるいは特定の口座へのキャッシュ退避）を警告します。 |
| **LQR (制御理論) の感度** | **キャッシュフロー改善のための「ツボ（介入点）」**<br>どのプレイヤー（ノード）に臨時の資金供給（流動性インジェクション）を行えば、システム全体の資金目詰まり（Stiffness）を最も効率的に解消できるかを示します。 |

### 熱力学的仕事（Work）と熱（Heat）の定義

* **Work（仕事 / `thermo_work_labels`）**: `USR_001`〜`USR_002`, `USR_005`〜`USR_010`
  * プレイヤーが事業・取引を駆動するために保有する「実体的な支払準備金（購買力）」を指します。
* **Heat（熱 / `thermo_heat_labels`）**: `USR_003`, `USR_004`
  * 取引のハブ（マーケットメーカー等）を通過する際の「決済の一時滞留・摩擦コスト」を熱的なロスとして扱います。

---

## 4. 時系列での挙動 (Cinematic Sequence)

1. **初期状態（Day 0）**:
   システム全体に供給された現金がプレイヤーに分散して存在し、その源泉である `ACC_Input_From_Outside`（純資産）とバランスしてスタートします。
2. **決済の循環**:
   株式売買の対価として、プレイヤー間で現金がたえまなく移動します。
3. **外部へのキャッシュ流出**:
   外部への支払い（手数料や市場外への流出など）は `ACC_Output_To_Outside`（費用）および `UNKNOWN_LEAK`（費用）として P/L を経由して流出していきます。この流出の累積が、B/S 上の「当期純利益（Net Income）の減少」として純資産を徐々にすり減らしていく様子が、完璧な会計的整合性をもって可視化されます。

---

## 5. モデルの前提と限界（反証可能性）

* **モデルの限界**:
  本モデルは「現金」の決済流動性のみを追跡しているため、その対価としてプレイヤーが取得・保有している「株式（アセット）」の価値は一切考慮されていません。
* **反証的注意**:
  あるプレイヤーの現金がゼロになっても、それは「倒産」を意味するとは限りません（大量の含み益を持つ株式を保有している可能性があるため）。現金の枯渇が本当に財務的な破綻であるかを監査するためには、必ず対となる **`Sample_6_Market_Stock_Flow` (Stock Flow Mode)** の株式評価額と併せて総合的に実査する必要があります。
