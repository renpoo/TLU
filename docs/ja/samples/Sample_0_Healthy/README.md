## 6. 🚨 Forensic Alert & 反証可能性 (Falsification Analytics)

### 6.1. 統計的偽陽性のトリアージ (False Positive Assessment)

* **観測事実:** 4月 (`4.7943`), 6月 (`3.3940`), 7月 (`4.8971`), 12月 (`3.8833`) において、流動性変化（velocity）の Z-Score（統計値）がしきい値 `3.0` を超えてアラートが発生。
* **物理的判断:**
    これは統計モデルの限界による「偽陽性」です。初期ステップにおける推定共分散がまだ十分に学習されていないこと（4月など）、および健全な商取引における一時的な決済集中（季節変動）が確率的ノイズとして強調されたものです。
    深層の保存則残差が `0.00` を維持し、スペクトル半径が `0.00` でロックされていないため、このアラートは「病的アノマリー（不正・エラー）」ではなく「一時的な正常ゆらぎ」として棄却（Dismiss）されます。

### 6.2. 本診断に対する反証条件 (Falsifiability)

もし本システムが「健全」ではないと反証するためには、以下の物理的原本または第三者証拠の提示が必要です：

1. **現預金の物理的不一致:** システム内の現金勘定の残高と、法人の銀行口座から直接出力された、偽造不可能な「銀行預金通帳原本」または「オンラインバンクのAPI生ログ原本」の間に、わずかでも調整不能な残高ズレが存在すること。
2. **簿外の隠し口座の存在:** 取引先登記や株主名簿などの第三者法務データに基づき、システムが捕捉しているネットワークトポロジーの外部（未知の取引先）で、実質的に流出資金を受け取っている別のノードが発見されること。
