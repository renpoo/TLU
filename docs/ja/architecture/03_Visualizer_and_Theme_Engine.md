# 03. 可視化とテーマ・エンジン (Visualizer and Theme Engine)

TLUパイプラインの最終フェーズ（プレゼンテーション）は、複雑な数理解析の結果を視覚的に整理し、人間の監査役が異常を直感的に発見できるようにサポートする役割を担います。

本ドキュメントでは、解析結果のグラフ描画（ダッシュボード化）に関する厳格なルールと仕組みについて解説します。

---

## 1. 最優先ルール：描画層における計算処理の禁止

可視化（Visualizer）層のプログラム内で、データに対するいかなる分析・計算処理を行うことも厳しく禁じられています。

* 平均値やZ-Scoreなどの統計指標を、この層で計算してはなりません。
* この層の唯一の責任は**「レンダリング（描画）」**です。前のフェーズで計算済みの純粋な数値を、そのままグラフの座標や色に変換する役割に徹します。この分離により、グラフの見た目が「コアの数学的計算結果を一切の歪みなく反映している」ことが保証されます。

## 2. 厳格なカラー適用（フェイルファスト・テーマエンジン）

もしグラフが、異常がないのに赤く塗られたり、異常があるのに目立たない色で塗られたりした場合、監査における致命的な判断ミスを誘発します。

これを防ぐため、TLUは**フェイルファスト・テーマエンジン**を採用しています。
特定の指標に割り当てられた「意味を持つ色（例：異常を示す赤色）」の設定が欠落していた場合、適当なデフォルト色で誤魔化して描画を続けることはせず、システムは即座にエラーとして停止します。誤解を招くダッシュボードを出力するくらいなら、処理を止める方が安全だからです。

## 3. ネットワークと異常の可視化

TLUの視覚的アプローチの代表例が、ネットワーク・トポロジー図を用いた異常（ストレス）の可視化です。

### ノード（口座や部門）の描画
* **指標:** 資金の絶対的な流入量と流出量の差分。
* **意味:** その口座が現在、資金を蓄積しているのか、それとも流出（出血）しているのかという状態を示します。

### エッジ（取引経路）の描画
* **指標:** その経路を通過する資金量のZ-Score（統計的異常度）。
* **意味:** 異常度が閾値を超えると、そのエッジ（線）は目立つ警告色（例：赤やオレンジ）へと変化します。これにより、巧妙に隠された不正な取引ルートを瞬時に特定することができます。

### 時系列の変化（アニメーション・連続フレーム）
時間経過ごとにグラフのフレームを生成することで、組織全体の資金の「脈動」やマクロな変化を観察できます。ある部門で発生した異常（ショック）が、取引経路を通じてどのように他部門へ波及していくかを視覚的に追跡可能です。

## 4. 3Dサーフェス（曲面）グラフの活用

TLUは、複数の指標を同時に把握するために3Dサーフェスグラフを多用します。

* **X軸 / Y軸:** 時間の経過、または口座（ノード）の並びを表します。
* **Z軸 (高さ):** 異常度（Z-Score）や、資金の滞留による摩擦など、算出された物理指標の高さを表します。

これらの厳格なルールに基づく可視化エンジンを通じて、TLUは複雑な取引データを、専門家にとって解釈可能で透明性の高い直感的なダッシュボードへと変換します。
