# 02. データのトポロジーと認識論的射影 (Data Topology and Epistemological Projection)

> **"システムの真実を計算するためには、まず名前という幻想を剥ぎ取らねばならない。"**

TLU がデータに物理学や幾何学の法則を適用する前に、データからドメイン（業務領域）特有のコンテキストをパージ（消去）する必要があります。アルゴリズムは「支払債務（買掛金）」「マーケティング部門」「米国東部サーバーリージョン」といった言葉を理解しません。アルゴリズムが理解するのは、トポロジー（位相）、質量、および方向性のあるフラックス（流量）のみです。

このドキュメントでは、事前集約された生のドメインデータを純粋な数学空間へと変換・射影するための厳格なプロトコルを定義します。

---

## 1. グレート・フィルター（ドメインの不可知論）

TLU パイプラインの最初のフェーズは **Phase 1: 射影（Projection）** です。その唯一の目的は「認識論的射影」です。つまり、厄介で人間が読める世界を、無菌で計算可能なテンソル空間へと翻訳することです。

* **語彙の剥奪:** データがプロジェクター (`_0_2_projector_to_coo.py`) を通過すると、すべての文字列ベースの識別子とドメインロジックが根絶されます。
* **COO テンソルストリーム:** この時点以降、パイプラインは標準的な Coordinate (COO) ストリームフォーマットでのみデータを受け入れます。
* **数学的純粋性:** コア解析フィルターは意図的に盲目にされています。それらは、自分が財務元帳の改竄を分析しているのか、生体ニューラルネットワークを分析しているのかを知りません。このドメインの不可知論が、人間のバイアスなしに数学的ルールが適用されることを保証します。

## 2. ユニオン・トポロジー（次元の整合性）

時間経過にわたって行列表算が数学的に有効であるためには、空間の次元が完全に一貫していなければなりません。

* **一貫した空間座標:** ノードに割り当てられた整数IDは、すべてのタイムステップにわたって、正確に同じエンティティを指していなければなりません。
* **全要素の和集合（Union）:** ある部門や口座がデータセットの最後の月にしか現れない場合でも、それは最初からトポロジー空間に登録されます。TLU は「ユニオン・トポロジー」を構築します。欠落しているフラックスは、単にゼロエネルギーの転送として扱われます。

## 3. エフェメラルな辞書（人間世界へのリンク）

コア・パイプラインがすべての人間用のラベルを破壊してしまうため、TLU は最終的な数学的結論を現実世界と突合（比較衡量）するために翻訳し直す方法を維持しなければなりません。

* **使い捨てのレジストリ:** 射影（Projection）フェーズ中に、TLU は `_node_map.csv` と `_time_map.csv` を生成します。
* **動的再構築:** これらの辞書は使い捨てであり、プロジェクターが実行されるたびに再構築されます。これにより、スキーマのマイグレーションなしでシステムが即座に適応することが保証されます。
* **Phase 3 での突合:** これらの辞書は、ビジュアル層でのみ再び参照され、人間が読める名前でラベル付けを行い、現実のビジネス現象との突合を可能にします。

## 4. フェイルファストな列マッピング

データの取り込み（Ingestion）は、あらゆる処理系において最も危険な障害発生ポイントです。TLU はデータ取り込みを妥協なく処理します。

* **厳格な要件:** プロジェクターは、明示的なCLI引数を要求します。
* **推測なし、フォールバックなし:** 列が欠落している場合、即座にパイプラインをクラッシュさせます。この **フェイルファスト** 設計により、改竄されたり破損したデータが入り口で捕捉され、下流の複雑な計算を気付かないうちに汚染することを防ぎます。
