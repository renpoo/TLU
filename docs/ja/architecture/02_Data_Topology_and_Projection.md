# 02. データ構造と射影 (Data Topology and Projection)

TLUの数学的アルゴリズムは、「買掛金」や「特定の部署名」といった人間が使う業務上の言葉（コンテキスト）を直接理解して計算するわけではありません。計算を正しく行うためには、入力された仕訳データを一旦、業務上の意味を持たない「純粋な数値のネットワーク（トポロジーと流量）」へと変換（射影）する必要があります。

本ドキュメントでは、生データを数学的計算が可能な形式へと変換するための厳格なルールについて解説します。

---

## 1. 業務コンテキストの排除（ドメイン非依存化）

TLUの最初の処理フェーズ（Phase 1: Projection）の目的は、人間が読むための会計データを、アルゴリズムが計算可能な「テンソル空間（数値の配列）」へと翻訳することです。

* **識別子の排除:** 変換プログラム（`_0_2_projector_to_coo.py`）を通過すると、勘定科目名や部門名などの文字列ベースの情報はすべて取り除かれます。
* **COO形式への統一:** このフェーズ以降、すべてのデータは数学的に扱いやすい標準的な行列形式（COOフォーマット）としてパイプラインを流れます。
* **数学的な客観性の担保:** コアの計算フィルターは、自身が「財務データを解析している」のか「別のネットワークを解析している」のかを知りません。この「意味の排除」により、人間のバイアス（先入観）を排除した純粋で客観的な計算が保証されます。

## 2. 空間座標の一貫性（ユニオン・トポロジー）

時系列に沿って数学的な行列計算を正しく行うためには、データの「枠組み（次元数）」が常に一定でなければなりません。

* **不変のID割り当て:** 特定の口座や科目に割り当てられた数値IDは、すべての期間を通じて同じ対象を指し示す必要があります。
* **全体集合の維持:** ある科目がデータセットの最終月にしか登場しない場合でも、TLUは最初の月からその科目の枠（次元）を準備しておきます（取引がない期間はゼロとして扱われます）。これにより、期間ごとの計算軸のズレを防ぎます。

## 3. 一時的なマッピング辞書（元の科目名への復元）

コアの計算パイプラインでは文字列名がすべて排除されるため、最終的に「どこに異常があったのか」を人間が確認するためには、数値を元の名前に戻す仕組みが必要です。

* **使い捨ての辞書生成:** 変換処理の際、TLUは一時的な対応表（`_node_map.csv` および `_time_map.csv`）を生成します。
* **動的な再構築:** これらの辞書は毎回作り直されるため、勘定科目の追加や変更があっても、システム側でデータベースの修正等を行う必要がありません。
* **結果の照合（突合）:** これらの辞書は最後の可視化フェーズでのみ参照され、異常が検出されたノードIDを「A支店の売掛金」といった人間が読める名前に復元し、実際の業務状況との照合を可能にします。

## 4. 厳格なデータバリデーション（フェイルファスト）

外部データの取り込みは、システムにおいて最もエラーが発生しやすい部分です。TLUはデータの不整合を妥協なく弾き返します。

* **必須項目の要求:** 変換プログラムは、必要な列（日付、借方、貸方など）が正確に指定されていることを要求します。
* **エラー時の即時停止:** データに欠落や不整合がある場合、TLUは推測による補完を行わず、即座にパイプラインを停止します。この設計（フェイルファスト）により、破損・改竄されたデータが下流の計算結果を静かに汚染し、誤った監査結果を生むリスクを未然に防ぎます。
