# 01. システム哲学と運用 (System Philosophy and Operations)

> **"複雑さは実行の敵である。機能の純粋さこそがその解毒剤である。"**

Tensor-Link Utility (TLU) は、モノリシックで状態を持ち、極度に絡み合った処理系を構築するという現代のトレンドを意図的に拒絶するように設計されています。代わりに、**Unixの哲学**に根ざした厳格で古典的なアプローチを採用しています。

このドキュメントでは、このフォレンジック処理系（Ver 8.0.0）を支配するコアなアーキテクチャの原則と運用プロトコルについて概説します。

---

## 1. Unix パイプライン・アーキテクチャ

TLU は、企業という有機体のダイナミクスを文字通り「ストリーム（流れ）」として扱い、情報の連続的なフローとしてデータを処理します。

* **ステートレス・フィルター:** 各数学フィルター（例：熱力学、運動学）は独立した実行可能ファイルです。これらは `Standard Input (stdin)` から標準の COO（座標）テンソルストリームを読み込み、物理学の単一のパラダイムを適用し、その結果を新しい列として追加して `Standard Output (stdout)` にフラッシュします。
* **隠し状態の排除:** フィルターは、実行間で内部データベースやメモリを保持しません。入力ストリームが同一であれば、出力も同一であることが数学的に保証されます。
* **パイプ接続 (`|`):** 複雑なクラスを記述することによってではなく、シンプルで純粋な関数を連結することによって、高度なアノマリー解析が達成されます。

## 2. 関心の分離：I/O vs. 純粋数学

テスト容易性を最大化し、開発者の認知負荷を軽減するために、TLU はデータ処理と数学的計算の間に厳格な物理的分離を強制します。

* **ラッパー層 (`filter_*.py`):** これらのスクリプトは意図的に「汚く（dirty）」作られています。CLI 引数のパース、CSVの読み込み、ドメイン辞書の解決、および書き込みを処理します。**この層には物理学、幾何学、あるいはビジネスロジックを含めることは一切許可されていません。**
* **コア数学層 (`core_*.py`):** これらは純粋な数学関数です。CSV、ドメインの語彙については何も知りません。純粋なテンソルを受け取り、テンソルを返します。これにより、数学的厳密性が保証されます。

## 3. ローカル依存性ゼロ

「私のマシンでは動く」という言い訳は、高精度な改竄検知環境においては容認できません。

* **ホストの無菌化:** ユーザーのホストOSに必要なのは `Docker` と `bash` のみです。Python、NumPy等の依存関係は、`tlu-engine` コンテナ内に厳密に閉じ込められています。
* **透過的なラッパー (`_tlu_env.sh`):** TLU は、ローカルコマンドをコンテナ化された実行へと透過的に翻訳します。

## 4. 宣言的実験制御（SSOT）

複雑な企業のシミュレーションにおいて、洞察の来歴（プロベナンス）は洞察そのものと同じくらい重要です。再現性を保証するため、TLU は Single Source of Truth (SSOT) に依存しています。

* **`_sys_params.csv` パラダイム:** 実験条件（入力データソース、ターゲットノード、アノマリー閾値など）を変更するためにソースコードを変更することは厳しく禁じられています。すべての境界条件は、`workspace/config/_sys_params.csv` で宣言的に定義されます。
* **コードとしてのパラメータ:** この設定ファイルは、実験の決定的な設計図として機能します。

## 5. イミュータブル・アーカイブの再現性

完全な監査可能性を強制するために、TLU はローカルのスナップショット・アーキテクチャを採用しています。

* **ワークスペースのスナップショット:** 重要なパイプラインの実行後、`bash bin/archive_experimental_run.sh` を実行するだけで、`workspace/` 全体（事前集約されたデータや設定を含む）をアーカイブできます。
* **タイムトラベル実行:** オーケストレーション・スクリプトを過去のアーカイブに向けることで、パイプラインはその歴史的なスナップショットの正確な瞬間と全く同じように振る舞い、比較衡量が可能になります。
